# ComputAI 出現在哪裡

TUI 只是其中一個介面。使用者真正想知道的只有三件事：

1. **現在還能不能用 Claude／Codex？什麼時候重置？該換哪個？**
2. **錢有沒有白花？**（訂閱回不回本、快取浪費、閒著還在計費的 GPU）
3. **機器和模型有沒有在做事，還是佔著資源？**

最方便的不是「打開某個畫面」，而是：**有事時被告知**，以及**出現在本來就會看的地方**。
依照「使用者要花多少力氣」排序：

| 力氣 | 介面 | 狀態 | 指令 |
|---|---|---|---|
| 零：自己來找你 | 桌面通知：額度到 80%、用完、**重置了可以繼續用**、機器連不上、模型佔記憶體沒在用、雲端 GPU 閒置計費 | ✓ | 在 `computai`／`--web`／`--watch` 裡自動跑；`--install-watch` 登入就在背景跑；`--notify-test` 試一則 |
| 零 | Discord／Telegram 即時通知、每週摘要 | ✓ | `[notify] chat = yes`；`--weekly --send` |
| 零：本來就在看 | Claude Code 狀態列 | ✓ | statusLine 設成 `computai --statusline`（Claude 額度本來就會自己從 `claude -p /usage` 讀，這只是多一個顯示的地方） |
| 零 | tmux、SwiftBar 選單列 | ✓ | `computai --line` |
| 零 | AI agent 自己查預算和額度 | ✓ | `computai --mcp` |
| 一眼 | 終端機總覽 | ✓ | `computai` |
| 一眼 | 瀏覽器、手機（Tailscale） | ✓ | `computai --web` |
| 問一個問題 | 「本地跑划不划算？」 | ✓ | `computai --bench` |
| 問一個問題 | 方案建議、快取浪費、月底預估 | ✓ | `computai --analyze` |

## 下一步候選（依價值排序）

1. **一鍵處理，不只顯示**：警示旁直接附上可以做的事，例如讓閒置模型卸載
   （Ollama `keep_alive: 0`）、停掉閒置計費的雲端 GPU（要確認才做）。
2. **選單列的完整版**：SwiftBar／xbar 外掛，選單列放最吃緊的額度，下拉選單列出每個額度、
   重置時間、今天的用量價值，點了直接開網頁版。
3. **手機加到主畫面**：網頁版加 manifest 和圖示，透過 Tailscale serve 打開就是一個 App。
4. **換手建議**：一個額度用完時，通知裡直接說「改用 Claude Code（5 小時額度還剩 58%）」
   （通知已經有，`--line` 和狀態列還沒有）。
5. **跑分歷史**：`--bench` 的結果記進帳本，換模型、換量化之後比較速度和每 token 電費。

## 原則

- 每個介面都用同一份判斷（`verdict()`、`limit_pace()`），不會一個說正常、另一個說快用完。
- 只在狀態**改變**時通知一次；重開程式、同時跑好幾個 computai 都不會重複。
- 能自動做的事都要先問；ComputAI 預設只看不動。
