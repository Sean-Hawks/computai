# ComputAI 介面設計規則

適用於終端機（live、`--once`）和網頁（`--web`）的 `cyber` 主題；`classic` 主題只沿用「資訊」那一半的規則。

一句話：**照 Minerva 的「先進極簡」——平滑、克制、技術感，不是硬核 HUD。** 字一律白，顏色只代表狀態；
能用大數字、細進度條、甜甜圈和折線表示的就不用句子；畫面最上面先回答「現在有沒有事」。

## 參考來源

- [Minerva](https://github.com/aifred0729-TW/Minerva) 的 `docs/DESIGN_LANGUAGE.md` 和 `components/Instrument.tsx`
  （AGPL，只參考原則，沒有複製程式碼）：明確拒絕「硬核 HUD」（切角、掃描線、括號編號、hex 位址、淡白字），
  狀態用「字＋點」、面板是「標題列／主體／來源列」三段、顏色依用途命名而不是依色相命名。
- Cyberpunk 2077 介面評論（[Interface In Game](https://interfaceingame.com/articles/cyberpunk-2077-ux-ui-critique/)）：
  整片同一個顏色、什麼都在閃，等於沒有重點；狀態只靠顏色分不出來。
- Jayse Hansen 談電影介面（[Pushing Pixels](https://www.pushing-pixels.org/2012/06/01/the-craft-of-screen-graphics-and-movie-user-interfaces-conversation-with-jayse-hansen.html)）：
  每個圖形都要有目的、大量留黑讓重點浮出來。
- [scifiinterfaces 對攻殼機動隊的評分](https://scifiinterfaces.com/2013/08/26/report-card-ghost-in-the-shell/)：
  半透明疊層傷害閱讀，顏色要拿來換對比。
- [eDEX-UI 的可讀性問題](https://github.com/GitSquared/edex-ui/issues/464)：好看但不能每天用。

## 1. 先回答「現在有沒有事」

畫面最上面是一條**總結列**，由同一份判斷（`verdict()`）算出：

| 等級 | 字 | 什麼時候 |
|---|---|---|
| 正常 | `● 一切正常` 綠字 | 沒有額度 ≥ 80%、沒有警示 |
| 注意 | `▲ 注意` 琥珀字 | 有額度 ≥ 80%、模型佔著記憶體沒在用、超過預算 |
| 要處理 | `▲ 警告` 紅字 | 額度用完、機器連不上、雲端 GPU 閒著還在計費 |

後面接最嚴重那一件事的白話句子（「Codex 每週額度用完，5h08m 後重置」）和「另外還有 N 件」。
等級是「記號＋字」，不用色塊。總覽上這一列由 Mission Control 的 LEDGER HEALTH 取代，其他分頁照樣顯示。

## 2. 顏色：字一律白，顏色只代表狀態

| 用途 | 終端機 / 網頁 | 只能用在 |
|---|---|---|
| `text` 內文、數值、品牌 | `#f5f5f5`／`#ffffff` | 所有文字、大數字、進度條走過的部分、目前分頁（反白） |
| `meta` 次要資訊 | `#aaaaaa` | 欄位名稱、單位、來源列。**只能**當成「標籤＋粗體數值」裡的標籤 |
| `line` 框線 | `#3a3a3a` | 圓角框線、分隔線、進度條沒走的部分 |
| `ok` 正常／活著 | 綠 `#4ade80` | `● ONLINE`、`LIVE`、推論中、回本、本地模型 |
| `warn` 注意 | 琥珀 `#fbbf24` | 額度 ≥ 80%、照速度會提早用完、閒置佔記憶體 |
| `fail` 故障 | 紅 `#f87171` | 額度用完、連不上、超過預算；面板裡有故障時框線也變紅 |

- 三個狀態色都站在 Tailwind `-400` 的亮度階（Minerva 的「綠色鐵則」：細字在黑底上會被拉暗，所以不用 -500）。
- **沒有青色、洋紅、霓虹。** 沒有色底黑字的標籤；唯一的反白是「目前在哪個分頁」。
- 進度條是同一個 `━` 字：走過的白（或狀態色）、沒走的灰；`┃` 標出週期還剩多少時間。
- 不准用低透明度的色塊當底（黑底上會變成髒的暗色）。

## 3. 文字

- 數值：`text` 粗體，等寬數字。標籤：`text` 一般字重，英文大寫加寬字距（網頁）。
- 次要資訊才用 `meta`；終端機**不用** SGR 2（dim），很多終端機會把它畫成幾乎看不見的灰。
- 網頁字級只有六階：11（標籤）、13（內文）、16（強調）、26（讀數）、32、44。
- 全大寫只用在短標籤，句子保持原本大小寫；主機名、模型名保持原樣。

## 4. 面板 = 標題列／主體／來源列

- **標題列**：左邊說「這是什麼」，右邊一個狀態字說「現在怎樣」（`2 台在線`、`1 個額度用完`）。
- **主體**：先摘要、再細節。
- **來源列**：數字從哪來、多新（`SSH · 4 秒前`、`價格：prices.ini，2026-10-03 查`）。沒有來源的數字不可信。
- 框線是 1px 細線、顏色 `line`；只有面板裡有 `fail` 的事情時框線才變紅。

## 5. 狀態一定是「字＋點」

`● 推論中`、`○ 閒置`、`已用完`、`連不上`。點只是裝飾，意思在字上，色盲和單色終端機也讀得懂。

## 6. 總覽：一眼回答三件事（M27）

配色和面板沿用 Minerva（第 2、4 節），版面以「看得清楚」優先，回答使用者最常問的三件事：
**額度還夠不夠、錢花得值不值、機器有沒有在做事**。

1. **總結列**（最上面）：`▲ 注意 wsl：有模型佔著記憶體卻沒在用`。
2. **額度橫幅**：每個額度一組——5×7 點陣大數字（剩幾 %）、粗量表（`┃` 標出週期剩下的時間）、一句白話
   （「照目前速度 9h51m 後用完（6d7h 後才重置）」）；寬度夠就兩個並排。右上角是整體狀態（正常／會提早用完／快用完）。
   沒接上的訂閱一行說怎麼接。窄於 100 欄時只有最吃緊的那個畫大，其他一行。
3. **四塊數字卡**：今天（和昨天比）、本月（回本條、實付月費）、本地推論（tok/s、哪台在跑什麼）、功耗（W、折線、本月度數）。
4. **機器表＋需要處理**：機器表有狀態字、CPU／GPU／記憶體的小量表、正在跑的模型和速度，下面是最近的平均負載折線；
   需要處理先放警示，剩下的空間放建議，放不下就截短並說還有幾條。版面會往下撐滿終端機的高度。

- **大數字**只畫數字和小數點，`$` 放左上、`%` 和單位放右下（小字），避免 3×5 字型裡 `5`／`S`、`$`／`£` 認不出來；
  放不下就去掉小數。
- 標籤跟著語言走（中文介面就是「額度」「今天」「需要處理」）。
- 其他分頁也用同一套面板和配色；開機畫面是 Minerva 的停靠面板（點導引檢查列、`STEP n / m`、細導軌）。

## 7. 裝飾的配額

可以：圓角細框、白色大數字、寬字距的狀態字、點字甜甜圈和折線、推論中的旋轉指示。

不可以（Minerva 的反模式）：切角或 `◤◥` 框角、`[01]` 編號徽章、色底黑字的標籤、警示條紋、
裝飾用的外文字、霓虹青／洋紅等飽和色、掃描線、glitch、閃爍、跑馬燈、假的十六進位或 log、
沒有資料的裝飾圖。

## 8. 終端機相容

- 只用 7 個角色色，256 色和 truecolor 都清楚；`NO_COLOR`、`--ascii` 時意思完全不靠顏色。
- 寬度不夠時句子折行、標頭在「·」之間換行，**不裁掉**重置時間這類關鍵資訊。
