- Multipliers: 5m write 1.25x, 1h write 2x, read 0.1x (0.025x Fable 5.1/Mythos 5.1; 0.05x Opus 5.5).
- Sonnet 5: $2/$10 is now standard; the announced Sept 1 2026 rise to $3/$15 will NOT occur (footnote 3).

- Batch = 50% off input and output. inference_geo "us" = 1.1x all categories (Claude 4.6+).
- Web search: $10 per 1,000 searches (+ tokens). Web fetch free. Code execution: free with web search/fetch, else $0.05/container-hour after 1,550 free hrs/month.
- Tokenizer note: Claude 4.7+ tokenizer yields ~30% more tokens for same text.

## 3. Claude Code statusline stdin JSON
Source: https://code.claude.com/docs/en/statusline
- `rate_limits.five_hour.used_percentage` (0-100) and `rate_limits.five_hour.resets_at` (Unix epoch SECONDS); same for `rate_limits.seven_day.*`. Example: five_hour 23.5 / 1738425600, seven_day 41.2 / 1738857600.
- `rate_limits` appears only for claude.ai Pro/Max subscribers (or behind Claude apps gateway with spend limit), only after first API response in session; each window may be independently absent; a window is dropped after its resets_at passes. Use `// empty` in jq.
- Gateway only: `rate_limits.spend_limit.used_percentage`, `.resets_at`, `.used_usd`, `.limit_usd`, `.period` (daily|weekly|monthly) (v2.1.251+/v2.1.284+).
- Cost: `cost.total_cost_usd` (client-side estimate at list price, may differ from bill, resets on /clear), `cost.total_duration_ms`, `cost.total_api_duration_ms`, `cost.total_lines_added`, `cost.total_lines_removed`.
- Context: `context_window.used_percentage`, `remaining_percentage` (input tokens only; may be null early), plus `current_usage`.
- Page also documents cache-state fields (warm, hit_ratio, timestamps) - not inspected in detail.

## 4. Anthropic Admin usage/cost APIs
Sources: https://platform.claude.com/docs/en/manage-claude/usage-cost-api ; .../api/beta/organization/usage_report/retrieve_messages ; .../api/beta/organization/cost_report/retrieve
- Auth: Admin API key `sk-ant-admin01-...` (or OAuth token with org:admin, or non-workspace-scoped key). Headers: `x-api-key`, `anthropic-version: 2023-06-01`. Not for individual accounts. Optional `anthropic-beta: fast-mode-2026-02-01` needed for `speed` group_by/filter.
- GET https://api.anthropic.com/v1/organizations/usage_report/messages
  - params: starting_at (RFC3339, required), ending_at, bucket_width (1m|1h|1d, default 1d), limit (1d: def 7 max 31; 1h: 24/168; 1m: 60/1440), page, group_by[] (account_id, api_key_id, context_window, inference_geo, model, service_account_id, service_tier, speed, workspace_id), filters: models[], api_key_ids[], workspace_ids[], service_tiers[] (batch, flex, flex_discount, priority, priority_on_demand, standard), context_window[] (0-200k, 200k-1M), inference_geos[], speeds[], account_ids[], service_account_ids[].
  - response: {data:[{starting_at, ending_at, results:[{uncached_input_tokens, cache_creation:{ephemeral_5m_input_tokens, ephemeral_1h_input_tokens}, cache_read_input_tokens, output_tokens, server_tool_use:{web_search_requests}, model, api_key_id, workspace_id, account_id, service_account_id, service_tier, context_window, inference_geo}]}], has_more, next_page}. Dimension fields are null unless grouped.
- GET https://api.anthropic.com/v1/organizations/cost_report
  - params: starting_at, ending_at, bucket_width (1d only), limit (def 7, max 31), page, group_by[] (description, workspace_id).
  - response results: amount (decimal string, in CENTS, e.g. "123.45" = $1.23), currency "USD", cost_type (tokens|web_search|code_execution|session_usage), description, model, token_type (uncached_input_tokens, output_tokens, cache_read_input_tokens, cache_creation.ephemeral_5m/1h_input_tokens), service_tier (batch|standard), context_window, inference_geo, workspace_id. Parsed fields (model etc.) only populated when group_by includes description. Priority Tier costs not included; code execution only in cost report.
  - Data lag ~5 min; polling once/min OK.
- Claude Code analytics: GET https://api.anthropic.com/v1/organizations/usage_report/claude_code ; params starting_at (YYYY-MM-DD UTC, single day), limit (def 20, max 1000), page. Same admin auth. Per-user/day records: actor (user_actor.email_address | api_actor.api_key_name), customer_type (api|subscription), terminal_type, core_metrics (num_sessions, lines_of_code, commits_by_claude_code, pull_requests_by_claude_code), tool_actions, model_breakdown[{model, tokens{input,output,cache_read,cache_creation}, estimated_cost{amount (cents), currency}}]. ~1h lag. API (Anthropic first-party) usage only. Source: https://platform.claude.com/docs/en/manage-claude/claude-code-analytics-api
- Enterprise (claude.ai) orgs use a different Analytics API key: https://platform.claude.com/docs/en/manage-claude/analytics-api (not fetched).
- Note: none of these cover Pro/Max subscription personal usage; for that use statusline rate_limits or local logs.

## 6. RunPod
Sources: https://docs.runpod.io/api-reference/pods/GET/pods ; https://docs.runpod.io/sdks/graphql/manage-pods
- REST: GET https://rest.runpod.io/v1/pods, header `Authorization: Bearer <API_KEY>`. Query: computeType, desiredStatus (RUNNING|EXITED|TERMINATED), gpuTypeId, dataCenterId, includeMachine, includeWorkers, includeTemplate...
  Response fields: id, name, desiredStatus, costPerHr (credits/hr; "actual cost may be lower if Savings Plans apply"), adjustedCostPerHr, gpu{id,count,displayName,securePrice,communityPrice,...}, machine{gpuTypeId, gpuType.displayName, dataCenterId, ...}, lastStartedAt, lastStatusChange, vcpuCount, memoryInGb, publicIp, portMappings. NO GPU utilization in REST schema.
- GraphQL: POST https://api.runpod.io/graphql, auth `?api_key=KEY` query param (doc example) or Bearer header. `query { myself { pods { id name runtime { uptimeInSeconds gpus { id gpuUtilPercent memoryUtilPercent } container { cpuPercent memoryPercent } } } } }` gives utilization telemetry (runtime is null when pod not running).
  Whether `costPerHr`/`desiredStatus`/`machine{gpuDisplayName}` are queryable in GraphQL: not shown on the doc page (a search snippet claimed so) - UNVERIFIED from docs; plan: GraphQL for utilization + REST for cost/status/GPU type, joined by id.

## 8. Lambda Cloud
Sources: https://docs.lambda.ai/api/cloud (cloud.lambda.ai/api/v1/docs 301s here)
- Auth: `Authorization: Bearer <API_KEY>` (Basic with key as username also supported). Responses wrapped `{"data": ...}`; errors `{"error":{code,message,...}}`. Rate limit 1 req/s.
- GET https://cloud.lambda.ai/api/v1/instances -> instances with id, name, ip, status (booting|active|unhealthy|terminated|terminating|preempted), region, instance_type{name, description, gpu_description, price_cents_per_hour, specs{vcpus, memory_gib, storage_gib, gpus}}. Price is embedded in instance_type of the instance object itself (per docs `price_cents_per_hour` is a required InstanceType field). Fallback: GET /api/v1/instance-types -> data{<name>:{instance_type{... price_cents_per_hour ...}, regions_with_capacity_available[]}}.
- GPU utilization: none documented.

## 9. Local inference servers
- LM Studio (https://lmstudio.ai/docs/developer/rest/endpoints): v0 REST API (/api/v0/chat/completions, /api/v0/completions, /api/v0/models) returns per-response `stats` {tokens_per_second, time_to_first_token, generation_time, stop_reason} and `usage` {prompt_tokens, completion_tokens, total_tokens}. No metrics endpoint documented. => must proxy/tally per-response, no cumulative counter.
- mlx_lm.server (https://github.com/ml-explore/mlx-lm/blob/main/mlx_lm/SERVER.md): only /v1/chat/completions and /v1/models; `usage` {prompt_tokens, completion_tokens, total_tokens} per response; no metrics endpoint.
- vLLM (https://docs.vllm.ai/en/latest/design/metrics.html), /metrics: vllm:prompt_tokens_total, vllm:generation_tokens_total (counters), vllm:num_requests_running, vllm:num_requests_waiting (gauges), vllm:kv_cache_usage_perc, vllm:request_prompt_tokens / request_generation_tokens (histograms), vllm:time_to_first_token_seconds, vllm:inter_token_latency_seconds, vllm:e2e_request_latency_seconds, vllm:prefix_cache_queries/hits. Label model_name.
- SGLang (https://docs.sglang.io/references/production_metrics.html): needs `--enable-metrics`, /metrics: sglang:prompt_tokens_total, sglang:generation_tokens_total, sglang:num_running_reqs, sglang:num_queue_reqs, sglang:token_usage, sglang:gen_throughput, sglang:cache_hit_rate, sglang:num_used_tokens, sglang:time_to_first_token_seconds, sglang:e2e_request_latency_seconds.
- llama.cpp server (https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md; raw README): needs `--metrics` (off by default). Metrics: llamacpp:prompt_tokens_total, llamacpp:prompt_seconds_total, llamacpp:prompt_tokens_seconds, llamacpp:tokens_predicted_total, llamacpp:tokens_predicted_seconds_total, llamacpp:predicted_tokens_seconds, llamacpp:requests_processing, llamacpp:requests_deferred, llamacpp:n_tokens_max, llamacpp:n_decode_total, llamacpp:n_busy_slots_per_decode, llamacpp:spec_decode_*. Also /slots and /health. Router mode needs ?model=<id>.
